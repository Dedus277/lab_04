Команда `algolab4-benchmark` запускает те же измерения. Готовые результаты находятся в [benchmark.csv](benchmark.csv).

```python
from algolab4 import Stack, fibonacci_iterative, fibonacci_recursive, generate_dataset, merge_sort

print(fibonacci_iterative(10), fibonacci_recursive(10))  # 55 55
print(merge_sort([3, -1, 3, 0]))  # [-1, 0, 3, 3]

stack = Stack()
stack.push("первый")
stack.push("второй")
print(stack.peek(), len(stack), bool(stack))  # второй 2 True
print(stack.pop())  # второй

values = generate_dataset("nearly_sorted", 100, seed=42)
```

## Ввод и исключения

- `fibonacci_iterative(n)` и `fibonacci_recursive(n)` используют нумерацию с нуля, где F(0) = 0 и F(1) = 1. Отрицательное целое вызывает `ValueError`, нецелое или `bool` — `TypeError`. В рекурсивной реализации состояние — пара соседних чисел F(k), F(k+1). Вызов сдвигает эту пару на одну позицию.
- `sys.getrecursionlimit()` возвращает текущий лимит глубины стека интерпретатора. В CPython он обычно равен 1000. Рекурсивной версии нужно n + 1 вызовов вспомогательной функции плюс кадры вызывающего кода. При исчерпании лимита Python возбуждает `RecursionError`. Для больших n можно использовать итеративную функцию.
- `insertion_sort(values)` и `merge_sort(values)` принимают список целых чисел, включая отрицательные значения и дубликаты. Пустой список допустим. Обе функции возвращают новый список и сохраняют исходный. Для аргумента другого типа или для элементов, отличных от целых чисел, включая `bool`, возникает `TypeError`.
- `Stack` хранит произвольные объекты. `push(item)` кладёт значение на вершину, `pop()` возвращает и снимает вершину, `peek()` возвращает вершину. `len(stack)` даёт размер, `bool(stack)` показывает, есть ли элементы. Вызовы `pop()` и `peek()` для пустого стека возбуждают `IndexError`.
- `generate_dataset(kind, size, seed=...)` создаёт новый список нужного размера. Доступны `random` (целые от −size до size), `sorted` (возрастание), `reverse` (убывание), `nearly_sorted` (примерно одна перестановка соседей на 100 элементов, минимум одна при size ≥ 2) и `duplicates` (целые от −2 до 2). Локальный генератор со значением `seed` обеспечивает воспроизводимость случайных наборов. Для `sorted` и `reverse` результат определяется размером. Неизвестный вид или отрицательный размер вызывает `ValueError`, нецелый размер или `bool` — `TypeError`.

## Анализ сложности

Для сортировок и генераторов n — длина списка. Для Fibonacci n — индекс числа. В оценках Fibonacci сложение считается одной операцией, а память измеряется в количестве чисел и кадров вызова. Python хранит целые числа произвольной точности, поэтому стоимость сложения растёт вместе с длиной чисел.

| Операция | Время | Дополнительная память |
| --- | --- | --- |
| Fibonacci, цикл | Θ(n) сложений | Θ(1) целых чисел |
| Fibonacci, рекурсия | Θ(n) сложений | Θ(n) кадров и целых чисел |
| Вставки | Θ(n) на отсортированном входе, Θ(n²) в среднем на случайном и в худшем случае | Θ(n) с копией результата, Θ(1) сверх неё |
| Слияние | Θ(n log n) | Θ(n) для срезов и результата, Θ(log n) кадров рекурсии |
| Стек | `push` и `pop` амортизированно O(1), `peek`, `len` и `bool` — O(1) | Θ(n) для хранения n элементов |
| Генерация | O(n) | O(n) вместе с результирующим списком |

## Benchmark

Размеры входа — 100 000, 1 000 000 и 10 000 000 элементов. Для каждой комбинации размера и типа создаётся один набор с `seed=42`. Перед каждым измерением создаётся независимая копия этого набора. Таймер `perf_counter_ns()` охватывает вызов сортировки, включая проверку типов и собственное копирование списка внутри функции. Генерация входа и создание копии для запуска происходят до старта таймера. Для каждой измеренной комбинации CSV содержит пять результатов и медиану в миллисекундах.

Вставки измерены на отсортированном и почти отсортированном входах. На обратном наборе число сдвигов растёт квадратично. Для случайного набора и набора с дубликатами квадратично растёт ожидаемое число сдвигов. Например, обратный список из 100 000 элементов требует около 5 млрд сдвигов, а из 10 000 000 — около 50 трлн. Поэтому эти комбинации по умолчанию получают статус `skipped_quadratic` с нулём повторов и пустыми полями времени. Флаг `--include-slow` включает весь набор замеров.

Медианы для 10 000 000 элементов на Windows с CPython 3.12.10 приведены в секундах.

| Тип входа | Вставки, с | Слияние, с |
| --- | ---: | ---: |
| Случайный | пропуск | 54,540 |
| Отсортированный | 1,524 | 6,787 |
| Обратный | пропуск | 6,958 |
| Почти отсортированный | 1,532 | 6,825 |
| С дубликатами | пропуск | 29,793 |

При росте списка со 100 000 до 10 000 000 элементов слияние на случайном наборе заняло примерно в 267 раз больше времени. По формуле n log n ожидался рост в 140 раз. Реальное время на больших списках также зависит от выделения памяти и работы кэша.

За тот же шаг время вставок выросло примерно в 120 раз на отсортированном наборе и в 101 раз на почти отсортированном. Линейная модель предсказывает рост в 100 раз. На этих двух типах входа число сдвигов равно нулю или пропорционально длине списка.

## Вопросы к защите

1. **Откуда берётся сложность сортировки слиянием?** Делим список пополам, пока в каждой части не останется один элемент. Потом соединяем отсортированные половины. На каждом из Θ(log n) уровней копируем суммарно n элементов, поэтому время равно Θ(n log n). Если числа из половин уже идут в нужном порядке, достаточно сложить списки в нужной последовательности.
2. **Какой инвариант стека проверяется тестом?** Вершина и длина сохраняются после просмотра. Тест `test_peek_preserves_top_and_size` дважды вызывает `peek()`, проверяет длину и затем убеждается, что `pop()` возвращает тот же объект.
3. **Зачем каждому запуску отдельная копия?** Сортировка на месте изменила бы общий список уже при первом запуске. Следующий запуск получил бы отсортированные данные, и время могло бы измениться из-за порядка входных элементов.
